(live page), accessed 2026-10-28, confidence: high, class: pricing
- This is a ~90% price cut vs. the predecessor Claude Haiku 4.5 ($1.00/$5.00 per MTok) — Source: aggregated release coverage (cellcog.ai "Claude Haiku 5.5 Released", developersdigest.tech migration guide), dated around 2026-10-07, accessed 2026-10-28, confidence: medium, class: pricing
- Realistic per-call cost for this app's use case (short task text in, short tag/priority/summary JSON out — roughly 200–500 input tokens, 50–150 output tokens): well under $0.0005 per call (back-of-envelope ≈ $0.00005–$0.0001), i.e. negligible for a course project's test volume — Source: derived calculation from the claude.com/pricing figures above, accessed 2026-10-28, confidence: high, class: pricing (derived, not a direct quote)
- Latency signals are mixed: one benchmark site reports ~0.7–1.0s for short Q&A-style completions on Haiku-tier models (Haiku 4.5: 0.96s short-answer; Haiku 5.5: 0.7s response latency per one tracker), while artificialanalysis.ai's own Haiku 5.5 "time to first answer token" figures show 9.6–13.4s for "low"/"medium" reasoning-effort variants — likely reflecting extended-thinking/reasoning overhead rather than a plain short classification call — Source: artificialanalysis.ai model pages + secondary aggregator (respan.ai), n.d./2026, accessed 2026-10-28, confidence: low-medium (contradictory), class: latency
- Best current estimate for this app's non-reasoning, short structured-output call: sub-second to low single-digit seconds (order of magnitude ~1–2s), but this is not pinned to an authoritative, dated Anthropic benchmark — Source: synthesis of above, confidence: low, class: latency
- New Anthropic Console accounts get a one-time ~$5 free credit (SMS verification, no credit card required), expiring roughly 14 days after claiming — Source: secondary aggregators (ssdnodes.com "Claude API: no free tier, but a credit"; grabaicredits.com), n.d./2026, accessed 2026-10-28, confidence: low-medium (not confirmed directly on an Anthropic-owned page), class: free-tier
- Reported rate limits for a brand-new/low-spend account: roughly 5 RPM / 20K input-tokens-per-minute / 4K output-tokens-per-minute at the lowest "Evaluation" tier, rising to ~50 RPM after the first $5 is added (Tier 1) — Source: aifreeapi.com "Claude API Quota Tiers and Limits Explained", n.d./2026, accessed 2026-10-28, confidence: low (third-party summary, not Anthropic's own docs page, should be re-verified at console.anthropic.com/limits before shipping), class: rate-limits
- These limits are far above what a solo student's to-do-list app would need (classifying individual tasks one at a time, interactively) — class: rate-limits, confidence: medium (reasoning from the limits above, not independently sourced)
- The current official integration pattern for structured output is `output_config: {format: {type: "json_schema", schema: {...}}}` on the Messages API (`POST /v1/messages`), which constrains the response to valid JSON matching a provided schema (GA feature; the older `output_format` parameter is deprecated) — Source: platform.claude.com/docs/en/build-with-claude/structured-outputs (official Anthropic API docs, fetched directly), n.d. (live page), accessed 2026-10-28, confidence: high, class: integration pattern
- Minimal raw-HTTP call authenticates via the `x-api-key` header (plus `anthropic-version` header) and can be made with no SDK at all (`curl`/`fetch`); the official Anthropic SDKs (`anthropic` for Python, `@anthropic-ai/sdk` for JS/TS) wrap the same endpoint, and the Python SDK additionally offers a `client.messages.parse()` helper for schema/Pydantic-model-typed output — Source: platform.claude.com structured-outputs doc (official), accessed 2026-10-28, confidence: high, class: integration pattern
- For a solo dev's browser/Node-based to-do app, the simplest viable pattern is: one `fetch`/SDK call per task with `output_config.format.json_schema` requesting `{tags, priority, summary}`, guarded by a try/catch with a short timeout, falling back to the local rule-based classifier on any error or on absence of an `ANTHROPIC_API_KEY` env var — class: integration pattern, confidence: medium (synthesized recommendation, not a direct citation)
- By default, Anthropic does **not** use Claude API inputs/outputs for model training: "By default, we will not use your inputs or outputs from our commercial products (e.g. Claude for Work, Anthropic API, Claude Gov, etc.) to train our models," with API data auto-deleted on the backend within 30 days unless the customer explicitly opts in (then retention can extend, and some newer "Covered Models" require 30-day retention and are excluded from Zero Data Retention) — Source: privacy.claude.com, "Is my data used for model training?" (Anthropic's own privacy center, fetched directly), page references a policy dated 2026-08-18, accessed 2026-10-28, confidence: high, class: privacy policy
- This default (no training, 30-day deletion) is explicitly different from consumer claude.ai Free/Pro/Max plans, where conversations may be used to improve models unless the user opts out — relevant only in that it confirms the API path (this candidate's path) is the privacy-safer one for sending student task text — Source: privacy.claude.com + corroborating secondary summaries (strac.io, humla.team), accessed 2026-10-28, confidence: high for the API/consumer distinction itself, medium for retention-period specifics, class: privacy policy

### Leads
- The latency numbers for Haiku 5.5 contradict each other across sources (sub-second vs. 9–13s "time to first answer token") — worth re-checking directly against Anthropic's own docs/performance notes, or running a quick empirical timing test with a real API key before committing to a UX assumption (e.g., whether a loading spinner is needed per task).
- The $5 free-trial-credit and rate-limit figures came only from third-party "how to get free API credits" aggregator sites, several of which look like SEO content farms (not Anthropic-owned). Verify directly at console.anthropic.com (Billing / Limits pages) before the project depends on them.
- A search for developer write-ups on "graceful fallback when no API key" gotchas returned low-provenance results not treated as evidence; the underlying engineering gotchas (check for key presence before calling, set explicit short timeouts, avoid infinite retry loops, keep the local classifier's output shape identical to the API's) are standard practice but not substantiated by a credible source here.

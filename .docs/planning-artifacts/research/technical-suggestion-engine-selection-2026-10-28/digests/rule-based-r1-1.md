## Candidate: Rule-based / keyword classifier only

### Findings
- The npm package `talkify-classifier-keywords` implements keyword-based topic classification instantiated directly from rule lists, explicitly requiring no training data — Source: npmjs.com, talkify-classifier-keywords package page, n.d., accessed 2026-10-28, confidence: medium, class: implementation pattern
- A working rule-based task-triage system (`bassam-111/ops-task-triage`, Flask) classifies tasks into 5 categories and 4 priority levels using "urgency words and deadlines," runs fully offline with no API key, and its own README flags "LLM-based classification option" as the top future-improvement item, implying known accuracy ceiling — Source: GitHub, bassam-111/ops-task-triage README, n.d., accessed 2026-10-28, confidence: high, class: implementation pattern / limitation
- A production project (`fazal305/nightbeacon`) documents in its own README "Limitations" section that its keyword-based priority classifier "can misjudge priority on ambiguous text," and a linked issue proposes adding a small LLM check only for borderline/ambiguous cases rather than replacing the rule engine — Source: GitHub, fazal305/nightbeacon Issue #13, n.d., accessed 2026-10-28, confidence: high, class: accuracy limitation (documented production experience)
- A homework-management app spec (`frankda94/homework-management-app` Issue #3) specifies a concrete, lightweight rule design for a suggestion engine: lowercase+tokenize text, weight two-word phrases at 3 and single tokens at 1, resolve ties/zero-matches to an "other" category, apply urgency/deferral keyword maps to set high/low priority (medium default), and enforce a 0.35 confidence floor — implemented as a pure synchronous function — Source: GitHub, frankda94/homework-management-app Issue #3, n.d., accessed 2026-10-28, confidence: medium, class: implementation pattern (spec only, not confirmed as built/measured)
- Among JS/TS libraries: `compromise` is a lightweight, rule-based NLP library (no model files, no training data) good for parsing grammar/entities but not built for classification; `natural` includes actual classifiers (Naive Bayes, logistic regression) requiring training; `wink-nlp` is positioned as a fast, small-footprint (under ~1,500 lines) rule/pattern-capable library with a custom-entity/rule mechanism (`learnCustomEntities`) — Source: npm-compare.com and PkgPulse "natural vs compromise vs wink-nlp" guide, n.d. (2026 guide), accessed 2026-10-28, confidence: medium, class: implementation pattern/library comparison
- One comparative study reports machine-learning text classification reaching ~87.5% accuracy versus ~69.4% for rule-based methods on the same task, indicating a real accuracy gap favoring ML — Source: ResearchGate, "A Comparative Analysis of Rule-Based and Machine Learning Decision Systems Under Normal and Edge-Case Conditions" (full text inaccessible, 403 — figures from search snippet only), n.d., accessed 2026-10-28, confidence: low, class: accuracy benchmark (unverified primary source, numbers not independently confirmed against full paper)
- Research on microtext classification found rule-based and ML approaches "perform well on different parts" of a text collection, and combining them outperforms either alone — suggesting rule-based engines are competitive on a subset of clear-cut cases even if weaker in aggregate — Source: arXiv, "Extracting actionable information from microtexts" (arxiv.org/pdf/2008.00343), n.d., accessed 2026-10-28, confidence: medium, class: accuracy benchmark / comparative finding
- Rule-based classification's core trade-off: no labeled training data is required, but it demands strong domain/keyword knowledge upfront and has documented generalization limitations versus ML — Source: search-aggregated findings citing text-classification survey literature (arXiv 2008.00364, "A Survey on Text Classification"), n.d., accessed 2026-10-28, confidence: medium, class: implementation complexity / limitation
- wink-nlp (a comparable lightweight rule/pattern-based JS NLP library) benchmarks itself at over 525,000 tokens/second — Source: winkjs.org / npm, wink-nlp package documentation, n.d., accessed 2026-10-28, confidence: medium, class: cost/latency (indirect evidence; not this exact app's rule engine, but representative of synchronous in-process rule/keyword matching speed in JS)
- No source found directly measuring wall-clock latency or marginal cost of a hand-written keyword/regex rule set specifically for a to-do app; however, by construction (no network call, synchronous string/regex operations), near-zero marginal cost and sub-millisecond latency is a logical/architectural certainty rather than an empirically benchmarked claim for this exact use case — confidence: high (architectural reasoning, not a citation), class: cost/latency
- No source found directly measuring privacy/data-exfiltration for a purely local rule-based classifier; however, since no network call exists in the described architecture (confirmed pattern in `ops-task-triage`'s "no API key required... runs offline"), no task text can leave the device by construction — Source: GitHub, bassam-111/ops-task-triage README ("no API key required"), n.d., accessed 2026-10-28, confidence: high, class: privacy

### Leads
- The nightbeacon project's resolution path — "small LLM check only for borderline items" — is a notable hybrid pattern: keep the rule engine as the default/fast path and escalate only low-confidence cases to an LLM. Worth considering as a v2 upgrade path rather than a v1 requirement.
- The homework-management-app spec's exact rule design (two-word phrase weight 3, single token weight 1, 0.35 confidence floor, tie-breaking to "other") is a concrete, directly reusable pattern for a to-do app's tag/priority suggestion engine, though it was found only as an issue/spec — no confirmation it was actually implemented or that its accuracy was measured.
- The 87.5%/69.4% ML-vs-rule-based accuracy comparison could not be verified against the full paper (blocked by a 403) — treat as a directional data point only, not a precise number to cite confidently.

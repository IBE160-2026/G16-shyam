# Kartet ## Thesis On an orienteering map the course layer never alters the terrain beneath it: the purple is printed over fixed ink and changes nothing it crosses. That is already this product's central promise, so the concept makes it literal. The user's sentence and the fields as they stand are terrain, in dark ink. A suggestion arrives as a purple layer laid over that record — offset, overlapping its edge, visibly a second pass — and edits nothing until a part is punched. It refuses the category default where an assistant's values arrive pre-filled in the fields with an undo offered afterwards, and the related default of one dominant **Accept all** with per-part actions folded behind a disclosure. ## World ISOM inks, each doing one job and only that job. Chrome (rail, header, tab bar) is map-margin paper `#EDE4D3`; the work area is runnable ground `#FCFBF8` with fields in `#FFFFFF` — white means settled: nothing proposed, nothing wrong, which is also why Settings with no API Key is drawn on white. Terrain ink `#1B1915`, secondary `#5C5345`. Contour brown is rules only, `#CBB08E` hairline and `#9B6B3F` emphasised — never a drawn contour map. Open yellow `#F2CB5A` is the due-this-week window. Thicket olive `#4E7033` is Need Attention and appears nowhere else. Marsh `#6BA3D6` / `#1F5878` / `#E2EEF7` is the inert: the Archive, and an engine that is not in use. Course purple `#8E2E7E` with wash `#F8EAF4` is reserved absolutely for a proposal not yet accepted, so purple on any screen means "not yours yet". Every pair was measured: 9px secondary on ground 7.3:1, ink on yellow 11.3:1, white on olive 5.7:1, purple on white 7.4:1, marsh ink on marsh-pale 6.5:1. Faces: **Barlow Condensed** 700 for control numerals, band labels, nav and all small-caps apparatus — the condensed grotesque of map control numbering. **Archivo** 400–600 for task text, body and the dense table. Tabular figures on every date, count and control number. Density is the control description sheet: 22px band rows, 32px desktop table rows, 46px mobile rows, apparatus at 9–11px, a strict column grid, hairlines instead of card edges, no nested boxes. ## Signature move **Punching the controls.** The proposal is a purple-ruled layer over the record, offset right and down, overlapping its corner, carrying three numbered controls — 1 Tags, 2 Priority, 3 Summary — joined by purple legs, with a dashed leg run from the sentence to control 1. Accepting *punches* it: the circle fills with ink, pin-prick marks appear, and the value settles into the record above in the terrain's own ink while the purple leaves that part. Rejecting strikes the circle through. A purple start triangle marks any task with a control still open. It lives on m2–m6 and d2–d5; m9 and d1 carry the unpunched three-control legend instead. ## Accept / edit / reject Every control carries its own **Accept / Edit / Reject** as three equal bordered 11px buttons — mobile stacks the controls, each with its own row of three; desktop sets the three controls side by side so all nine actions are visible at once. Accept all / Reject all sit below the panel as smaller, lighter outline buttons captioned "Shortcuts. They do nothing the three controls cannot", so the per-part path is three times more present than the shortcut. Edit opens a standard segmented control (low / medium / high) with Apply / Cancel and states that your value is written, not the proposal. Undo is a real bordered button, on the punched control and beside the settled field (m5, d4). Priority is a three-bar ladder **plus** the word; provenance is a drawn mark **plus** "RULE ENGINE" spelled out — neither is encoded by colour alone. ## 360 and 1280 Mobile runs the legs vertically: one purple column offset 14px right of the record, controls read in sequence, the list below in banded groups under a tab bar. Desktop turns the legs horizontal: the record becomes a wide field table and the course panel sits to its right, overlapping its corner, with the three controls as columns — one glance instead of three. The list becomes a true control description sheet (task / tags / priority / due) beside a rail of Smart Lists and tag counts, with a week ladder aside. The review panel is composed for each width, not reflowed. ## Honest risk Purple is the strongest thing here and it is absent exactly where the user spends most of their time. On m1, d1, m7, d6 and Settings there is no pending suggestion and therefore no purple at all: those screens are carried by the inks and the density alone — the yellow window band, the olive thicket band, marsh rows in the Archive, brown rules, tabular columns. I think that holds, and it is why the Smart List groups are banded rather than faintly tinted. But it is a quieter world than the review surface, and whoever builds this will be tempted to borrow purple for a selected row or a primary button, which destroys the single reservation the whole palette depends on. Second cost: the tinted grounds are legible but unforgiving. Each small-type pair had to be checked by hand, and the next contributor who adds an unverified tint will break contrast before they notice it. Interface strings are English as the working assumption; the PRD leaves interface language open and this concept does not settle it.
